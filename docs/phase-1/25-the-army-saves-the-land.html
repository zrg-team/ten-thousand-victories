What changes, in one picture

Scope decision — gate to Dragon Ascent first

defenderPower (WarSystem), landGarrisonPower (PowerSystem) and resolveInvaderBattle (InvasionSystem) are shared by rival, campaign and empire. Every dial below lands behind an ascent-only gate (mode check or a config constant the classic modes keep at today's value), and verify-modes-regression must print a byte-identical 60-tick fingerprint for the other three modes. Empire adoption is a separate, later, measured decision (the year-4-fairness round showed rules gated off empire cause their own unfairness — decide with numbers, not now).

Every value is a probe. The repo's law is measure-don't-reason: expect at least one re-tune loop, and remember the free coupling — waves floor against lagged defence, so halving masonry also softens the threat curve; wave targets likely need nudging up, not down.

04

Implementation steps

  1. Capture the baseline before touching anything. 16-seed /funscore, plus the 60-tick verify-modes-regression fingerprint, on a HEAD copy served from a second port. Use the archive technique — never a worktree, never a stash: git archive HEAD | tar -x -C <scratch>/baseline · junction node_modules · vite --port 5200 · stop vite before rm -rf; delete the junction with (Get-Item …).Delete()
  2. Extract the masonry constant. Replace the literal 16 with MASONRY_POWER_PER_DEFENSE (and the share cap) in one place both callers import; classic modes read the legacy value, ascent reads the probe. src/systems/ascent/PowerSystem.ts · src/systems/WarSystem.ts (defenderPower) · new constants in src/game/ascentConfig.ts
  3. Count every host present. .find → .filter in defenderPower, summing all non-levy hosts of the owner on the land (the levy stays excluded — it is the walls). Run the fingerprint immediately: if classic modes move, gate this too and note it. src/systems/WarSystem.ts:213–248 — the comment block there documents the defect and blesses exactly this pass
  4. Add the siege state. Two optional fields on Land — siege?: {{ attackerId, ticksLeft }} and lostAtWave?. Optional so old saves parse untouched. src/state/types.ts · loaders need no migration for optional fields
  5. Arrival starts a siege, not a battle. In the invader-arrival path (ascent-gated): set siege with ticksLeft = ⌈defense/12⌉ instead of resolving; tick it down in the invasion phase of advanceAscentTick; on zero, resolve the assault as today (which now counts every host that marched in). src/systems/InvasionSystem.ts (resolveInvaderBattle callers) · src/systems/ascent/AscentTick.ts invasion step
  6. Make the siege loud. Besieged flag on the province's map render + province card, one advisor line ("Vân Đồn is under siege — 3 ticks to the walls"), and the war board row shows the clock. No new screens. src/scenes/conquest/screens/warBoard.ts · advisor strip · province card renderer
  7. The relief march. A host ordered to a besieged own province marches as normal; on arrival it joins the defence set. If the fight is "worth watching", the watchable battle opens with every present host enrolled (BattleSystem already does this); otherwise the roll now includes them via step 3. Pay a small loyalty/economy reward on a relieved siege so rescue visibly matters. src/systems/ascent/ConquestSystem.ts (standing orders / march targets) · src/systems/BattleSystem.ts (verify enrolment, don't rebuild it)
  8. The retake window. On a player land lost, stamp lostAtWave. attackLand grants +25% attacker power against that land, decaying linearly to zero over 3 waves. Stacks with the existing seat-liberation rule; walls staying down after a loss is already shipped (land-consequences round) — this completes lose → muster → take it back. src/systems/WarSystem.ts (attackLand) · loss detection in detectConquests / invasion resolution
  9. Muster economics dial. −15% muster supply cost (ascent-gated constant). The spreadsheet answer to "how do I defend?" must become "raise a host" — walls already escalate in price per purchase. src/systems/WarSystem.ts (getMusterEstimate) · src/systems/ascent/MusterSystem.ts
  10. Measure, tune, repeat. A/B against the step-1 baseline: 16-seed funscore, the behavioral gates below, and only then adjust wave targets if the softened defence floor made waves lag. test_scripts/verify/verify-land-consequences.mjs (extend) · new verify-siege-relief.mjs
05

Verification gate

16-seed /funscore ≥ baseline (8 seeds has a ±4 noise floor and once reversed a verdict — never trust it)
≥ 50% of sieges see a relief march arrive in autoplay probes (new verify-siege-relief.mjs, counting siege-opened vs relief-joined events)
Army share of contested defence power lands at 45–60% by wave 5 (probe harness prints the three-way split)
verify-modes-regression fingerprint byte-identical for rival / campaign / empire
verify-land-consequences.mjs still green, extended with: siege delays resolution · relief joins the fight · retake bonus decays to zero
/smoke green — no console errors, no blank frame, all four modes boot

Traps (all previously hit in this repo)

  • verify-ascent.mjs always exits 0 — parse stdout for PASS: vs CHECK:.
  • ConquestSystem.ts has mixed CRLF/LF — an LF-only exact-match patch silently misses the middle of the file.
  • A harness that strips the realm to one province trips isDefeated, after which every tick is a no-op — reset the flag when probing curves.
  • Several battle harnesses (verify-battle-dials, verify-battle-motion, verify-scroll) fail intermittently on HEAD — always run a suspect harness against the baseline before believing you broke it.
  • A long-lived dev server can serve a stale Phaser — check Phaser.VERSION before trusting local behavior.
